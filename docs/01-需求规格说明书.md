## 二、功能需求明细

### FR-01 一键接入（链接 + 凭证）
- 每个数据源最少仅需两个字段：`baseUrl`（一个链接）与 `credential`（一个凭证）。
- 其余参数（项目/仓库范围、路径过滤、同步周期）均有**默认值**，可留空。
- 提供"测试连接"能力：`POST /api/sources/test`，不落库，直接返回可拉取的条目数与样例标题。
- 凭证不明文落盘：使用 `AES-256-GCM` 加密，密钥由环境变量 `KB_MASTER_KEY` 派生（见 FR-12 安全章节）。

### FR-02 归一化与统一检索
- 统一文档模型见 `docs/02-架构设计.md`。
- 索引：中英文混合分词（中文 bigram + 英文词元），BM25 打分，标题加权。
- 检索结果跨源聚合，按相关度排序，支持按平台/标签/时间过滤。

### FR-03 ~ FR-08 六大内置平台
详见 `docs/05-数据源接入手册.md`，各适配器能力矩阵：

| 平台 | 认证方式 | 拉取内容 | 断点/分页 | 备注 |
|---|---|---|---|---|
| ShowDoc | `api_key` + `api_token`（亦支持 Cookie） | 项目 → 目录 → 页面正文 | 支持 | 兼容官方 Open API 多版本端点 |
| GitHub | Personal Access Token（PAT） | 仓库 → Markdown/文本文档 | 支持 | 支持按 owner/repo 白名单与路径过滤 |
| Gitee | Access Token（v5） | 仓库 → Markdown/文本文档 | 支持 | 支持企业版域名 |
| 禅道 | 用户名+密码换取 token（REST v1），或 SessionID（旧版） | 产品/项目/需求/任务/Bug/文档 | 支持 | 需求-任务-Bug 关联保留 |
| 印象笔记 | ENEX 导出包（主），或 Evernote Cloud API token（可选依赖） | 笔记标题/正文/标签/笔记本 | 支持 | ENEX 路径可为本地目录或可访问 URL |
| 腾讯文档 | 开放平台 Access Token；或以导出文件 + 本地目录方式接入 | 在线文档 / 表格摘要 / 导出文件 | 支持 | 端点模板可覆盖，兼容版本差异 |

### FR-09 MCP 双向能力
- **作为 MCP 客户端（接入别人）**：配置一个 stdio 命令或 SSE 地址，平台调用 MCP 协议的 `resources/list`、`resources/read`（以及可选 `tools/call`）拉取内容，归一化入库。
- **作为 MCP 服务端（被别人接入）**：本平台对外暴露 MCP 工具与资源，任意支持 MCP 的客户端（Claude Desktop、各类 IDE / Agent）可直接检索和阅读知识库。

| 方向 | 协议 | 工具/资源 |
|---|---|---|
| 出站（本平台 → 外部 MCP） | stdio / SSE（HTTP） | `resources/list`、`resources/read`、`tools/list`、`tools/call` |
| 入站（外部 Agent → 本平台） | stdio（JSON-RPC 2.0） | 工具 `kb_search` / `kb_get_document` / `kb_list_sources` / `kb_list_documents` / `kb_sync_source`；资源 `kb://doc/{id}` |

### FR-10 工作台
- 数据源管理（增删改查、启停、手动同步、同步状态与耗时）
- 全局搜索（跨源、关键词高亮、相似片段）
- 文档阅读（Markdown 渲染、原文链接跳转、复制）
- 标签与收藏、最近更新、统计面板

### FR-11 云上部署 / FR-12 本地部署
见 `docs/03-部署指南.md`。要点：
- 本地：零 npm 依赖，`node server/src/index.js` 即起，数据目录 `./data`，默认监听 `127.0.0.1`。
- 云端：Docker 单镜像（Node 20 slim）、Compose 一键、云托管（CloudBase）配置、GitHub Actions 自动构建推送 GHCR。

### FR-13 知识与经验统一
- 统一模型 + 统一标签 + 统一时间线
- 支持全量导出（JSON / Markdown 包），避免厂商锁定
- 支持"经验条目"：任何文档可标记为 `type=experience`，在工作台独立视图聚合

### FR-14 三端

| 端 | 形态 | 入口 |
|---|---|---|
| Web | 浏览器（桌面级布局） | `http://host:8787` |
| 移动 | 响应式 H5 + PWA（可添加到主屏、离线缓存） | 同一地址，自动适配 |
| 桌面 | Electron 壳（内嵌本地服务 + 窗口） | `npm run desktop` |

### FR-15 ~ FR-18 交付
- 仓库：`https://github.com/zhangshifa/knowledge-workbench`
- 需求原文与规格说明均入库
- 提交信息明确说明本次交付内容

## 三、非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 依赖 | 服务端零第三方依赖（仅 Node ≥ 18 内置模块），避免供应链风险与离线安装失败 |
| NFR-02 | 凭证安全 | AES-256-GCM 落盘加密；API 返回永不回显明文凭证；支持只读最小权限凭证 |
| NFR-03 | 容错 | 任一数据源失败不影响其他源；同步记录错误明细；重试退避 |
| NFR-04 | 性能 | 万级文档规模下检索 < 200ms；增量同步依赖 `updatedAt` 比对 |
| NFR-05 | 可移植 | 数据目录可整体拷贝/挂载；支持 `KB_DATA_DIR` 覆盖 |
| NFR-06 | 可观测 | 同步历史、数量统计、健康检查 `/api/health` |
| NFR-07 | 合规 | 仅读取被授权内容；不缓存凭证到日志；日志脱敏 |

## 四、验收标准

1. 提供 1 个链接 + 1 个凭证即可完成一个数据源的创建与首次同步。
2. 六大平台适配器均可独立配置；未配置的平台不影响系统启动。
3. 通过 MCP 客户端（任意支持 MCP 的工具）能检索到本平台已同步的文档。
4. 本平台能通过 MCP 方式把一个外部 MCP 服务器的内容接入并检索。
5. `docker compose up -d` 可在云主机完成部署；`node server/src/index.js` 可在本地完成部署。
6. Web / 桌面 / 移动三端均可访问同一服务并完成检索与阅读。
7. 需求原文在仓库中保持原封不动。
