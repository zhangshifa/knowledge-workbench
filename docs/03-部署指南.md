# 03 · 部署指南（本地 / 网页 / 桌面 / 移动 / 云）

本平台**服务端零第三方依赖**，部署的本质只有一句话：让服务（Python 或 Node）跑起来，并把 `./data` 目录持久化。

---

## 一、本地 + 网页部署（推荐：Python）

Python 服务同时提供 REST API 与静态网页托管，所以**启动它就是网页端**，浏览器直接访问即可。

### 方式 A：一键启动器（最省事）

- Windows：双击 `start-windows.bat`
- Linux / macOS：`./start.sh`

启动器自动完成：设置数据目录 → 选择运行时（Python 优先，没装则回退 Node）→ 3 秒后打开浏览器 → 前台运行（Ctrl+C 停止）。

### 方式 B：命令行

```bash
# 准备：Python ≥ 3.9（无需 pip install）
python --version

cd server_py
python main.py serve                 # 默认 127.0.0.1:8787
python main.py serve --host 0.0.0.0  # 局域网 / 公网可访问

# 自定义端口与数据目录
KB_PORT=9000 KB_DATA_DIR=/srv/kb-data python main.py serve
```

### 方式 C：Node 运行时（等价可选）

```bash
node server/src/index.js             # Node ≥ 18，零依赖
KB_PORT=9000 node server/src/index.js
```

- 数据落 `./data`（可用 `KB_DATA_DIR` 覆盖），包含 `sources.json`、`docs/*.json`、`index.json` 与加密凭证。
- 迁移机器：直接把整个 `data/` 目录拷过去即可；Python 与 Node 的数据格式兼容。
- 仅本机使用无需 HTTPS；若要让同网段（或 APK）访问，将 `KB_HOST=0.0.0.0` 并设置 `KB_API_TOKEN`。

## 二、桌面端（Electron）

```bash
cd desktop
npm install            # 安装 electron（仅开发依赖）
npm run desktop        # 拉起本地服务 + 窗口
```

- 桌面端 = 轻量壳：自动探测运行时（**默认 Python**，可用 `KB_RUNTIME=node` 强制切换），
  本机 spawn 服务子进程，窗口加载 `http://127.0.0.1:8787`。
- 与服务端、Web 端共享同一份 `data/`。
- 打包：`npx electron-packager . knowledge-workbench --out=dist --overwrite`。

---

## 三、移动端（PWA）

移动端**不需要单独打包**。用手机浏览器打开工作台地址后，通过「添加到主屏幕」即可获得近似原生 App 的体验：

- `web/manifest.webmanifest` 提供图标、名称、全屏样式。
- `web/sw.js` 缓存静态外壳，弱网/离线也能打开工作台界面（检索需联网）。
- 前端为响应式布局，窄屏自动切换为抽屉式侧边栏。

## 四、云上部署（容器）

### 4.1 Docker 一键

```bash
docker build -t knowledge-workbench .
docker run -d --name kb -p 8787:8787 \
  -e KB_HOST=0.0.0.0 \
  -e KB_MASTER_KEY="$(openssl rand -hex 32)" \
  -v kb-data:/app/data \
  knowledge-workbench
```

### 4.2 Docker Compose

```bash
docker compose up -d --build
```

`docker-compose.yml` 已挂载 `kb-data` 卷，并设置健康检查。可在 `.env` 或 `environment` 注入 `KB_API_TOKEN`、`KB_MASTER_KEY`（**切勿提交明文**）。

### 4.3 持续集成（GHCR）

`.github/workflows/ci.yml` 在推送 `main` 时自动：
1. 对 `server/src` 全部 `.js` 执行 `node --check`；
2. 构建镜像并推送至 `ghcr.io/zhangshifa/knowledge-workbench`（latest / sha / semver）。

之后云端可直接 `docker pull ghcr.io/zhangshifa/knowledge-workbench:latest`。

### 4.4 云托管（腾讯云 CloudBase）

`deploy/cloudbase/cloudbaserc.json` 已配置 `@cloudbase/framework-plugin-container`，使用本仓库 `Dockerfile` 一键部署。
将 `envId` 替换为你的环境 ID，执行 `tcb framework deploy` 即可。

### 4.5 反向代理 + HTTPS

`deploy/nginx.conf` 给出把工作台暴露于域名的示例（含 SSL、超时、体大小配置）。务必在代理后启用 HTTPS，并配置 `KB_API_TOKEN`。

## 五、环境变量一览

| 变量 | 默认 | 说明 |
|---|---|---|
| `KB_HOST` | 127.0.0.1 | 监听地址（云上设 0.0.0.0） |
| `KB_PORT` | 8787 | 监听端口 |
| `KB_DATA_DIR` | ./data | 数据目录 |
| `KB_API_TOKEN` | 空 | 设置后 /api/* 需 Bearer |
| `KB_MASTER_KEY` | 随机密钥文件 | 凭证加密主密钥 |
| `KB_SYNC_INTERVAL_MINUTES` | 120 | 定时同步周期，0=仅手动 |
| `KB_SYNC_ON_BOOT` | false | 启动即对启用源各同步一次 |
| `KB_MAX_DOCS_PER_SOURCE` | 5000 | 单源单次上限 |
| `KB_HTTP_PROXY` | 空 | 外部请求代理（企业内网） |

> 完整示例见 `.env.example`（已列入 `.gitignore`，不入库）。
